# 多 EAS 客户端模型

## 目标

开发人员可以在同一台电脑上保存多个金蝶 EAS 客户端，例如 7.5、8.0、8.8、9.0 或无法可靠识别版本的定制客户端。切换客户端时，数据中心与账号边界必须同时切换，不能复用另一客户端的状态。

## 配置边界

`clients[]` 是一等领域对象。每个客户端独立保存：

- `id`：稳定内部 ID。
- `remark`：用户可修改的备注，是 UI 中的主要识别名称。
- `client_directory`：EAS 根目录、client 目录或 bin 目录均可输入，核心层统一归一化。
- `desktop_file` / `command` / `working_directory`：特殊安装方式的启动覆盖项。
- `detected_version`：仅在存在可信产品版本证据时记录；无法确认时为空并显示“EAS 兼容模式”。
- `data_centers`：只属于此客户端的数据中心集合。

全局只保存 `active_client_id`，表示当前客户端。账号必须保存 `client_id`，因此相同名称的数据中心可以安全存在于不同 EAS 客户端中。

## 运行时规则

1. 单账号登录使用账号自己的 `client_id`，不依赖 UI 当前选择来猜启动路径。
2. 批量登录同时提交 `clientId + dataCenter`，协调器只选择两者都匹配的启用账号。
3. 数据中心发现以指定客户端为边界；本地缓存、历史保存值和账号回退都不会跨客户端合并。
4. 删除客户端前必须确认没有账号引用；有引用时拒绝删除。
5. 客户端目录结构有效但版本无法可靠识别时进入兼容模式，不凭 XML schema、Java 版本等弱信号猜 EAS 产品版本。

## 从 0.26.x 迁移

旧配置中的全局 `launcher`、`ui.data_centers` 和无 `client_id` 的账号会在首次读取时迁移到 `legacy-default` 客户端。迁移前原文件保存为：

```text
config.yaml.pre-multi-client.bak
```

迁移后的主配置使用原子写入。若迁移写盘失败，程序仍使用内存中的兼容结果，不因为迁移失败阻断登录。
