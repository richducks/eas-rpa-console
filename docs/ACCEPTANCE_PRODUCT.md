# 产品验收：Jobs 式产品审查

本轮不评价内部架构，只看一个第一次使用的人能否在没有说明书的情况下理解产品、完成设置并登录。目标不是“像某种界面”，而是删除不必要的选择、降低认知负担、让主任务天然突出。

## 结论

**通过首轮产品验收。** 当前主线版本：`0.26.0`。

## 验收清单

- [x] **第一眼知道做什么**：首屏标题为“登录 EAS”，主按钮只有一个“登录已启用账号”。
- [x] **首次使用路径明确**：首屏直接展示 `EAS 客户端 → 数据中心 → 登录账号` 三步，不要求先理解配置、Keyring、RPA 或窗口自动化。
- [x] **状态必须真实**：配置文件里仅有默认路径字符串不算“客户端已就绪”；只有运行探测确认或用户实际选择目录后才显示就绪。
- [x] **密码状态参与就绪判断**：有账号但安全存储中没有密码时，不显示“可以登录”，批量按钮保持不可执行。
- [x] **技术概念降级**：Keyring / DPAPI / AT-SPI / PowerShell 不作为一级入口；密码只向用户表达为“系统安全存储”。
- [x] **导航收敛**：主导航仅保留“登录 / 诊断 / 日志”；设置放到齿轮入口。
- [x] **诊断按需出现**：正常使用不需要进入诊断；诊断页用“已准备 / 未准备”说明问题，而不是先展示工具矩阵。
- [x] **账号操作就地完成**：添加、编辑、启用、单账号登录都在账号列表完成，不再跳转独立“账号管理/凭据管理”页面。
- [x] **视觉层级单一**：一套设计 token、一种卡片体系、一种主按钮语义；删除历史多主题样式叠加。
- [x] **触控路径短**：日常批量登录为“选数据中心 → 登录已启用账号”；单账号为“账号行 → 登录”。
- [x] **失败能找到下一步**：主任务失败提示用户去诊断；日志保持为第三层信息，不打断主流程。
- [x] **首次打开真实截图已验收**：见 `docs/screenshots/acceptance-first-run.png`。

## 本轮删除的视觉/产品噪音

- 删除独立的“Keyring 凭据”页面和“写入凭据”一级按钮。
- 删除账号管理与主登录列表的重复信息架构。
- 删除首次打开时的演示账号、演示活动和演示日志，避免把假数据当真实状态。
- 删除多轮 CSS 主题覆盖，避免同一按钮在不同规则中反复改变圆角、颜色和层级。
- 删除首页无关的工程能力术语；它们只保留在诊断或开发文档。
- 删除可拖拽列宽、数据中心拖拽排序等非核心交互，先保证登录主路径稳定。

## 首次打开验收场景

在一个全新的 `XDG_CONFIG_HOME` 下启动，不复用开发机历史配置：

1. 顶部显示“需要设置”，不是伪造“系统就绪”。
2. 三步设置全部可见，第一步指向选择 EAS 客户端。
3. 没有数据中心时，数据中心区域明确说明“选择 EAS 客户端后点击刷新”。
4. 没有数据中心时，添加账号不会让用户进入无法完成的表单。
5. 主登录按钮不可执行，直到客户端、数据中心、账号和密码达到真实可运行状态。
