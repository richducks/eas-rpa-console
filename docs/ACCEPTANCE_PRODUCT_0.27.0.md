# 0.27.0 产品验收：Jobs 式产品审查

本轮只审用户体验，不用工程复杂度为界面问题辩护。

## 1. 信息层级

- [x] 主任务仍然是“登录 EAS”，多客户端能力只增加一条紧凑的“当前客户端”切换层。
- [x] 当前客户端使用用户自己的备注作为主名称；版本、数据中心数量作为次级信息。
- [x] 完整路径、启动器、高级启动方式只存在于客户端管理/编辑，不占据主界面。
- [x] 诊断与日志继续保持次级入口。

## 2. 第一次打开就会用

- [x] 空配置仍显示明确的三步路径：添加客户端 → 读取数据中心 → 添加登录账号。
- [x] 第一步直接进入客户端编辑器，不要求用户理解 launcher、Desktop 文件或平台实现。
- [x] 目录可选择 EAS 根目录、client 目录或 bin 目录；程序自己归一化。
- [x] 自动识别不到版本时显示“EAS 兼容模式”，不制造错误版本号。
- [x] 客户端添加完成后第一步动作改为“管理”，不继续提示“添加”。

## 3. 触控/点击路径

常用路径：

1. 顶部下拉框一次点击切换常用 EAS 客户端。
2. 选数据中心。
3. 点账号“登录”或“登录已启用账号”。

维护路径：

1. 点“管理客户端”。
2. 可直接“使用”另一个客户端，或“编辑”备注/目录。
3. 添加新客户端只需要备注 + 目录；高级启动方式默认折叠。

- [x] 切换客户端不需要进入设置页。
- [x] 修改备注不需要重新建立账号。
- [x] 删除带账号的客户端会给出明确阻止信息，而不是静默丢账号。

## 4. 视觉噪音与一致性

- [x] 客户端下拉框只显示备注，不重复显示“备注中的版本 + 自动版本”。
- [x] “当前客户端”使用普通横向小标题，取消竖排装饰文字。
- [x] 客户端管理沿用现有卡片、按钮、模态框和明暗主题规则，没有引入第二套视觉系统。
- [x] 缺密码时三步摘要明确显示“补全缺失密码后即可登录”，不会错误显示“设置已完成”。
- [x] 只有已启用账号参与“密码是否齐全”的登录就绪判断。
